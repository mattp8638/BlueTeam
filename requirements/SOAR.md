
SOAR Orchestration and Execution Core MVP Specification
Here is the granular MVP specification for the High-Performance SOAR Orchestration & Execution Core, specifically focusing on the microservices runtime and automation execution layer. Per your instructions, all UI, dashboard, and front-end generation are excluded from this phase.
Core Objective
Build an event-driven, containerized automation subsystem capable of executing complex mitigation chains at line-rate via a secure, stateless microservices daemon architecture without relying on heavy Python wrappers
.
1. Architectural Requirements (The Execution Engine)
To achieve a highly available, non-blocking distributed task platform, the AI must build the following backend structure:
Task Broker Engine: Automation requests must route through a distributed queue backend utilizing Temporal.io or a Go-based task broker like Asynq, backed by a Redis or Kafka in-memory database tier
.
Ephemeral Micro-Runners: The stateless orchestrator daemons must never execute arbitrary scripts directly on the host operating system. The AI must configure the orchestrator to spawn isolated, unprivileged container instances (Docker or Podman APIs running on an internal gVisor runtime kernel)
. The worker pulls the target action parameters, runs the API code, returns the output payload, and instantly destroys itself
.
Zero-Disk Credentials: Integrate a HashiCorp Vault core. The execution worker must request short-lived AppRole authorization tokens on-the-fly, holding the secret strictly within volatile memory space (RAM) and clearing it instantly upon container destruction
.
OCSF Action Schema (Data Standard): All automation execution payloads must natively map to the OCSF Activity Class 6007 (Incident Action) schema to prevent field-mapping overhead when communicating back to the SIEM or Ticketing modules
.
2. Functional MVP Capabilities (Headless Logic)
The core engine must support the following backend capabilities without any graphical interfaces:
Dynamic JSONPath Argument Injection: Implement an internal parser that reads input event shapes using JSONPath notation to dynamically extract variables (e.g., $.event.src_endpoint_ip) from upstream telemetry and inject them directly into downstream action arguments at runtime
.
Deterministic Fork-Join & Barrier Syncing: The core engine must implement a barrier controller for parallelized tasks (e.g., simultaneously checking VirusTotal and scanning endpoint memory). This controller must force parallel paths to synchronize at a "join" node, validating all execution responses before passing combined outputs down to subsequent steps
.
Native Connector SDK Framework: To prevent custom-code sprawl, the AI must build a lightweight SDK framework (in Go or Python) where creating a single declarative configuration file automatically generates the execution clients and data parsers for new vendor integrations
.
3. AI Cognitive Integration (Self-Healing & Fallbacks)
Traditional SOAR platforms are brittle; this MVP must utilize local Small Language Models (SLMs) to survive API failures:
Automated Execution Trace Self-Healing: If a third-party vendor updates an API field and the integration node returns a 400 Bad Request or schema error trace, the engine must route the failure context down to the local AI. The model must read the target vendor documentation, fix the argument names in the JSON payload, and safely retry the task
.
Context-Aware Fallback Synthesis: If a critical containment step fails (e.g., an endpoint's EDR agent is offline), the model must scan live hardware mapping details from the Vulnerability Management records and dynamically configure a fallback step, such as drafting a hypervisor-level network routing block
.
Execution Sandbox Guardrails: Every automated script or dynamic API payload generated by the language engine must pass through a static analysis validation scanner prior to execution. This defense is mandatory to stop Indirect Prompt Injection (OWASP LLM01) attacks hidden inside log alerts
.
Training Data Hand-off: Direct your AI coding tool to fine-tune the local SOAR models using the Foundation-Sec-8B base model, the Cybersecurity SFT Dataset (for building structured JSON payloads and parsing runtime trace exceptions), and the AI Agent Tool Debugging Prompt Library
.
--------------------------------------------------------------------------------
4. MVP Exit Requirements (Definition of Done)
The SOAR Execution Core MVP is considered functionally complete when it passes the following automated, headless backend tests:
Micro-Runner Isolation Test: The Task Broker receives a command, successfully spins up a gVisor-backed Docker/Podman container, executes a simulated network block API call, passes the 200 OK response payload back to the daemon, and securely destroys the container within milliseconds
.
Volatile Memory Secrets Test: During execution, the micro-runner securely authenticates to the HashiCorp Vault API, injects the token strictly into RAM, and completes the API request without writing any credential data to the local disk
.
JSONPath Variable Injection Test: The engine successfully reads an upstream OCSF alert, extracts an IP address via JSONPath syntax, and seamlessly maps that variable into the required execution arguments of the downstream action
.
Barrier Synchronization Test: The engine successfully forks a workflow into three parallel automated tasks, pauses execution at the barrier controller until all three return a status code, and merges the outputs into a single valid JSON payload
.
Autonomous API Healing Test: A worker is intentionally fed a payload with a deprecated API variable name resulting in a 400 Bad Request error. The local AI catches the trace, patches the JSON schema structure dynamically, and re-executes the payload to a successful completion state
.
Guardrail Violation Intercept Test: A simulated log containing malicious command-line injection instructions is passed to the AI fallback synthesizer. The static analysis scanner successfully flags and drops the execution request before the container is allowed to run it
.
